# ADR-0002: Уніфіковані ідентифікатори UUIDv7 для всіх сутностей

## Status

Accepted

## Context and Problem Statement

Який тип даних використовувати для первинних (PK) та зовнішніх (FK) ключів у всіх сутностях B2B CRM-системи? Під час початкової генерації AI застосував тип `int` для `Client.client_id`, що спричинило неузгодженість типів ключів у моделі. Потрібно обрати єдиний стандарт ідентифікаторів для всієї системи.

## Considered Options

1. **UUIDv7 (RFC 9562) для всіх PK та FK.**
2. **Auto-increment Integer (BigSerial / BIGINT).**
3. **UUIDv4 (випадковий UUID).**

### Оцінка варіантів

#### Варіант 1: UUIDv7 (обрано)
- **Плюси (+):**
  - Глобальна унікальність: дозволяє децентралізовану генерацію ідентифікаторів клієнтами чи мікросервісами без звернення до центральної БД.
  - Часова сортованість (time-ordered): містить мілісекундний timestamp на початку, що запобігає фрагментації B-tree індексів у СУБД (на відміну від UUIDv4).
  - Уніфікація: єдиний тип для всіх ідентифікаторів у системі спрощує валідацію та серіалізацію API.
- **Мінуси (-):**
  - Займає 128 біт (16 байт) пам'яті порівняно з 32/64 біт для цілих чисел.
  - Відносно новий стандарт (RFC 9562, травень 2024 р.), потребує перевірки підтримки в обраному технологічному стеку.

#### Варіант 2: Auto-increment Integer (BIGINT)
- **Плюси (+):**
  - Компактний розмір (4–8 байт), висока швидкість індексації.
  - Легко читається людиною під час тестування та налагодження.
- **Мінуси (-):**
  - Створює точку синхронізації в БД; унеможливлює безпечну офлайн/мікросервісну генерацію ID.
  - Передбачуваність ID становить загрозу безпеці (enumeration attacks / витік бізнес-метрик).

#### Варіант 3: UUIDv4
- **Плюси (+):**
  - Глобальна унікальність, підтримка в усіх сучасних платформах і мовах програмування.
- **Мінуси (-):**
  - Повна випадковість призводить до значної фрагментації індексів і падіння продуктивності вставок у великих таблицях.
  - Відсутня природна сортованість за часом створення.

## Decision Outcome

Обрано варіант 1: **UUIDv7 для всіх PK та FK ідентифікаторів**.

UUIDv7 поєднує переваги глобальної унікальності розподілених систем із високою швидкістю індексації традиційних автоінкрементів завдяки вбудованому часовому префіксу.

### Positive Consequences

- Повна узгодженість типів у всій моделі даних (`Manager`, `Client`, `Deal`, `Product`).
- Безпека від перебору ідентифікаторів та сумісність із розподіленою архітектурою.
- Висока продуктивність операцій запису завдяки послідовності ключів у B-tree індексах.

### Negative Consequences

- Більший розмір збереження ключів та індексів порівняно з цілочисельними типами.
- Менша зручність читання рядкових представлень у логах і при ручних запитах.
