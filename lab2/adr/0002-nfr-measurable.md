# ADR-0002: Фіксація нефункціональних вимог (NFR) із числовими межами

## Status

Accepted

## Context and Problem Statement

Як формулювати нефункціональні вимоги (NFR) для B2B CRM-системи? Якісні абстрактні описи (наприклад, *"система повинна працювати швидко"*, *"інтерфейс має бути зручним"*, *"дані повинні надійно зберігатися"*) є суб'єктивними, не підлягають автоматизованому тестуванню та прямо порушують критерії завдання: *"кожна з числами й межами (хто, з яких пристроїв, навантаження з межами, час відгуку, безпека...)"*.

## Considered Options

1. **Суворо квантифіковані NFR із числовими пороговими значеннями та метриками.**
2. **Якісні описові NFR без числових обмежень.**

### Оцінка варіантів

#### Варіант 1: Квантифіковані NFR із числами та межами (обрано)
- **Плюси (+):**
  - Однозначність і тестованість: вимогу можна перевірити автоматизованими навантажувальними тестами (JMeter/k6), моніторингом аптайму (Prometheus/Grafana) або сканерами безпеки.
  - Повна відповідність Definition of Done курсу та запобігання відхиленню роботи під час перевірки.
  - Чіткі SLA/SLO для команди розробки та інфраструктури (наприклад, <= 2.0 с при 100 активних менеджерах).
- **Мінуси (-):**
  - Вимагає детального аналізу бізнес-навантаження та встановлення обґрунтованих меж для кожної категорії (продуктивність, доступність, безпека, аудит).

#### Варіант 2: Якісні NFR
- **Плюси (+):**
  - Швидше формулюються без додаткових розрахунків.
- **Мінуси (-):**
  - Неможливо перевірити на етапі приймального тестування (що саме вважається "швидким"?).
  - Пряме порушення вимог завдання Lab 2 (*"без NFR робота не зараховується, кожна з числами й межами"*).

## Decision Outcome

Обрано варіант 1: **Суворо квантифіковані NFR (NFR-01..NFR-07)**.

Кожна нефункціональна вимога зафіксована з числовими характеристиками:
- NFR-01 (Продуктивність): час відгуку <= 2.0 с (p95) при <= 100 активних менеджерах.
- NFR-02 (Надійність): доступність >= 99.5% у години 08:00–20:00 (пн–пт).
- NFR-03 (Безпека): TLS >= 1.2, bcrypt cost >= 12, таймаут сесії <= 60 хв.
- NFR-04 (Зручність): клієнтська валідація <= 300 мс, підтримка 2 мов.
- NFR-05 (Сумісність): ширина екрана від 360 px, останні 2 версії браузерів.
- NFR-06 (Масштабованість): >= 100 000 угод, пошук <= 500 мс.
- NFR-07 (Аудит): зберігання логів >= 90 днів із фіксацією UUIDv7 та результату.

### Positive Consequences

- Сформовано однозначні критерії приймання для архітектурних та навантажувальних тестів.
- Вимоги не наносяться на діаграму UC і не трасуються в функціональній матриці, що відповідає стандарту.

### Negative Consequences

- Вимагає налаштування систем моніторингу та метрик (Prometheus, APM) для постійного вимірювання зафіксованих порогових значень у продакшені.
