# DEFENSE — Лаб 5 (Архітектура: Component Diagram)

## 1. Як модель інтегрує весь ланцюг моделей (Lab 1–4)

Компонентна модель побудована за п'ятирівневою схемою (UI → API Controllers → Service Layer → Data Access Repositories → PostgreSQL Database) із чіткою межею `CRM System Boundary` та чотирма зовнішніми інтеграціями.

Що саме узгоджено з попередніми роботами:
- **Модель даних (Lab 1):** таблиці в `PostgreSQL Database` і чотири репозиторії (`DealRepository`, `ClientRepository`, `ProductRepository`, `ManagerRepository`) прямо відповідають чотирьом сутностям ER-моделі (`Manager`, `Client`, `Deal`, `Product`) у 3NF.
- **Вимоги та прецеденти (Lab 2):**
  - актори `Manager`, `Client`, `Administrator` взаємодіють із відповідними модулями рівня UI;
  - основний прецедент `UC-3 Create Deal` (FR-01..FR-07, сценарії S1–S4) реалізований ланцюжком `DealManagementUI` → `DealController` → `DealService`;
  - прецедент знижки `UC-6 Apply Discount` виділений у компонент `PricingEngine` (`IPricingEngine`);
  - автентифікація (`UC-1`, FR-05, S5, NFR-03) реалізована через `AuthController`, `AuthService` та зовнішній `Identity Provider`;
  - вимога журналювання всіх спроб створення угод (NFR-07) покрита компонентом `AuditLogService` (`IAuditLog`).
- **Взаємодія (Lab 3):** усі учасники Sequence-діаграм S1–S5 (`DealController`, `AuthService`, `DealService`, `ClientRepository`, `ProductRepository`, `Database`) перенесені в компонентну модель зі збереженням напрямків викликів. Прямий запис `DealService -> Database` із S1 деталізовано через `DealRepository`.
- **Бізнес-процес (Lab 4):** паралельна перевірка клієнта й товарів (`Fork` / `Join`) виконується викликами `DealService` до `ClientService` та `ProductService`, а крок 6 (надсилання клієнту повідомлення «Підтвердьте умови угоди» з контролем 3-денного таймауту) виконує внутрішній `NotificationService` через зовнішній шлюз `Notification Gateway`.

## 4. Ключові рішення

- **ADR-0001:** обґрунтовано 5-рівневу модульну архітектуру з обов'язковим проходженням викликів через сервісний шар.

- **Артефакти:** модель збережена у `model/component-diagram.mmd` та `model/component-diagram.puml`, рендери перегенеровані у `model/component-diagram.png` та `model/component-diagram.svg`.
